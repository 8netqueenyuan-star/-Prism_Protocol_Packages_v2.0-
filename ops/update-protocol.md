# 持续更新协议｜Update Protocol

## 更新触发

触发更新的情况包括：客户复盘发现失效假设、行业规则变化、案例反复出现的新模式、Prompt 产生系统性误导，或适配器出现边界风险。

## 更新步骤

1. 记录问题、来源、影响的产品/适配器和严重程度。
2. 区分：事实更正、语言优化、工作流变化或内核原则变化。
3. 由产品拥有者审查；内核原则变化需明确记录理由，不能静默覆盖。
4. 更新版本号与变更说明，并用一个代表性案例回归测试。
5. 通知受影响的伙伴或客户；必要时标注旧版本不再适用。

## 节奏

每个活跃产品至少每季度审查一次；重要风险变化即时审查。复盘关注真实使用、误解风险、关系与长期果效，不只看使用量。
